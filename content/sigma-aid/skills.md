# Skills

An Agent Skill is a directory with a `SKILL.md` file that contains YAML front matter and Markdown instructions. It can also contain reference files and scripts.

Sigma-aid loads skills from explicitly configured directories and makes them available through office positions. It does not automatically discover skills in a project or home directory. A skill provides instructions only: it cannot grant tools, credentials, or file system access, and loading a skill does not execute its scripts.

## Where skills are loaded from

### Register roots in skills.conf

The daemon reads `skills.conf` from its configuration directory:

- By default, it reads `/etc/sigma-aid/skills.conf`.
- With `sigma-aid --config <directory>`, it reads `<directory>/skills.conf`.
- If the file is absent, the daemon starts with no registered skills.

List absolute paths to the directories that contain your skills. Both forms below are accepted:

```yaml
skills:
  roots:
    - /opt/company/skills
    - path: /srv/team/skills
```

Directories such as `~/.agents/skills`, `~/.claude/skills`, and workspace skill directories are not scanned unless you register their absolute paths here.

### Package layout

Each skill occupies one directory directly beneath a registered root:

```text
/opt/company/skills/
  code-review/
    SKILL.md
    references/
      checklist.md
    scripts/
      check.sh
```

The loader checks one directory level below each root for `<skill-name>/SKILL.md`. It does not search recursively for more skill definitions.

A minimal `SKILL.md` is:

```markdown
---
name: code-review
description: Review changes against the team checklist.
---
Read references/checklist.md before reviewing the changes.
```

The front matter must contain `name` and `description`. The name must match the containing directory and may contain lowercase letters, digits, and hyphens. Duplicate skill names across registered roots are rejected.

### Skills generated by setup

Setup activation can install the bundled training skills:

1. It reads templates from `<config-directory>/training-material/skills`.
2. It renders them into `<state-root>/training-skills`.
3. It registers the generated directory in `skills.conf`.
4. It adds available default skills to positions in `roles.conf`. It leaves an existing `skills:` entry unchanged.

The state root is the parent directory of the configured SQLite database. Packaged training templates are installed under `/etc/sigma-aid/training-material`.

Restart the daemon to load the generated skills and attachments.

## Attach skills to office positions

Registering a root does not give every model access to its skills. Attach each skill to the positions that may use it in `roles.conf`:

```yaml
roles:
  positions:
    reviewer:
      skills:
        - code-review
        - house-style: { pinned: true }
```

For an ordinary attachment, the position's system prompt includes the skill's name and description. The model loads the instructions when needed with `skill_load`.

For a pinned attachment, the skill body is included directly in the system prompt.

Access checks use the daemon's office identity for the current turn, not a position supplied in tool arguments. A skill cannot extend that identity's permissions.

## Load instructions and reference files

The skill tools require the daemon tool worker pool, with `daemon_tool_workers` greater than zero. They are advertised only to eligible identities.

| Tool | Purpose |
|---|---|
| `skill_load` | Returns the skill body cached at startup, its version, the digest of `SKILL.md`, and a listing of current package files. |
| `skill_read` | Reads a UTF-8 text file beneath the skill directory. Paths outside that directory and symlinks are refused. |

For example:

```text
skill_load {"name":"code-review"}
skill_read {"name":"code-review","relpath":"references/checklist.md"}
```

These tools serve instructions and text files. They do not execute scripts. Script execution requires a separate tool and the corresponding deployment permissions.

## Support and limits

Sigma-aid supports startup validation, access checks by position, loading skill bodies on demand, pinned instructions, bounded file reads, and protection against path traversal and symlinks.

The following limits matter when deploying skills:

- **Definitions and attachments require a restart.** The daemon captures the skill registry, skill bodies, and position attachments at startup. There is no live registry reload.
- **Reference files are read live.** Startup hashes the package files, but `skill_read` does not check manifest membership or compare the returned bytes with those hashes. Changed or newly added files can be served while the reported `SKILL.md` digest remains unchanged. Do not treat that digest as verification of all text returned during a turn.
- **The default retained body limit is 64 KiB.** Longer skill bodies are truncated. Keep the main instructions short and place supporting material in reference files.
- **`allowed-tools` is metadata, not a permission grant.** Deployment configuration remains the authority for available tools.
- **`user-invocable` is parsed but is not an implemented explicit invocation feature in the assessed source.** `disable-model-invocation` is enforced.

## Source basis

This description is based on the sigma-aid source at tag `v2.1.13`, not on an inspection of a running deployment's configuration.

The main implementation files are:

| File | Responsibility |
|---|---|
| `src/sigma-aid/config/loader.hpp` | Configuration file loading. |
| `src/sigma-aid/config/parser.hpp` | Configuration parsing. |
| `src/sigma-aid/config/skills.hpp` | Skill discovery, validation, and package loading. |
| `src/sigma-aid/config/types.hpp` | Skill attachments and prompt configuration. |
| `src/sigma-aid/tools/local_skills.hpp` | `skill_load` and `skill_read`. |
| `src/sigma-aid/setup/activation.hpp` | Training skill generation and registration during setup. |
| `src/sigma-aid.cpp` | Daemon integration. |

Dedicated tests are in `test/rework_config_skills.cpp` and `test/rework_tools_skills.cpp`. They were not run for this documentation assessment.
